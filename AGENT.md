# AGENT.md

Guidance for AI coding agents working in this repository.

## Project overview

Jose Laurencio's personal portfolio — the "Mission Control" engineering
portfolio. Next.js (App Router) with a static export (`output: 'export'`),
TypeScript, Tailwind CSS v4, Framer Motion, and MDX content via Velite. Full
spec lives in `docs/`:

- `docs/PRD.md` — vision, IA, pages, data model, content workflow
- `docs/DESIGN_SYSTEM.md` — typography, color (with computed contrast
  ratios), spacing, motion, component specs, accessibility rules
- `docs/ARCHITECTURE.md` — the exact file/folder layout, and where every
  component/page/util/content type is supposed to live

Read those before adding anything nontrivial — most "where does this go"
and "what color/spacing/animation" questions are already answered there.

**Hosting note:** the GitHub repo was renamed from `joselaurencio.github.io`
to `personal-page`. A repo must be named exactly `<username>.github.io` to
get GitHub's automatic user-page hosting at the root domain — under
`personal-page`, GitHub Pages (once enabled) would serve as a *project*
page at `joselaurencio.github.io/personal-page/` instead, which needs a
`basePath`/`assetPrefix` in `next.config.ts` that isn't set yet (PRD/
ARCHITECTURE assumed a user-page repo with none needed). If the intent is
still to serve from the bare `joselaurencio.github.io` domain, that now
requires a custom-domain (CNAME) setup instead. Don't assume either way —
confirm with Jose before touching `next.config.ts` or deploy config.

The previous plain-HTML site (`index.html` / `styles.css` / `script.js`)
has been deleted — the Next.js app is the only site now.

## Working in this repo

- `npm run dev` — dev server. `npm run build` — Velite content build +
  static export to `out/`. `npm run lint` / `npm run typecheck`.
- Content (`content/projects/<slug>/index.mdx`, `content/notebook/*.mdx`,
  etc.) is validated by `velite.config.ts` at build time — publishing a new
  project is meant to be "one folder + one Markdown file," per PRD §16.
  Don't hand-edit `content/data/{github,ftc,youtube}.json` — those are
  meant to be regenerated by `scripts/fetch-*.ts` (not yet wired to CI;
  currently hand-seeded with real data, see commit history).
- Follow `docs/DESIGN_SYSTEM.md` tokens (colors, spacing, type scale,
  motion timing) instead of inventing new ad hoc values — the palette's
  contrast ratios were deliberately computed against WCAG, not eyeballed.
- No fabricated content: don't invent projects, competition results, or
  bio details. Verify real facts (e.g. via the FTCScout API, the YouTube
  channel RSS feed) rather than guessing — a prior pass in this repo
  guessed a YouTube channel ID that turned out to belong to an unrelated
  channel; it was caught by cross-checking against the channel's canonical
  URL, not assumed correct on the first plausible-looking match.
- After UI changes, verify visually (dev server + browser/screenshot), not
  just via typecheck/lint — this repo does not have a component test suite.

## Deployment

Pushing to `main` is intended to build (`velite build && next build`) and
deploy the static export to GitHub Pages via GitHub Actions
(`docs/PRD.md` §17) — that workflow isn't wired up yet (`.github/workflows/`
doesn't exist). Until it is, treat `main` as production and coordinate
before pushing.
